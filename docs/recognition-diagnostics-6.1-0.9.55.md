# HarmonyOS 6.1 识别兼容与异常日志（0.9.55-test）

## 问题与改动

Pura 70 Pro / OpenHarmony-6.1.1.120 报告 API 24。旧版本只在 API 26 及以上使用完整布局识别，
API 24 会进入逐控件查询的旧路径，无法享受相同的结构、倒计时、已启用规则及图片证据识别。
驾校一点通实机记录只留下“未找到跳过/关闭文字”，每轮查询耗时数秒。

本轮采集到其“跳过”文字与独立数字倒计时，完整引擎识别为 S03，点击目标为外层 Flex：
`[1023,267][1193,355]`。脱敏样本只保留结构、状态、几何和“跳过 / 5”，纳入回归。

新增统一 LayoutCapture：API 26 沿用原生 `Driver.dumpLayout`；API 24 通过既有本机 HDC
身份，在 `127.0.0.1` 查询系统布局，返回后立即关闭连接，临时文件随命令清理。没有新建
调试身份、没有修改激活记录或启动另一个监督任务，没有向外网发送布局。只在需要布局
时连接，不做定时截图。命令读取上限 3 秒、连接总等待有限、响应限制 4 MiB。

读取入口复用于识别、点击前复核、消失确认、手动学习布局、视觉证据复核及桌面名称。
识别引擎、两帧核对、已启用规则授权和坐标时效门槛保持一致；没有为驾校一点通硬编码坐标。
这条兼容路径要求无线调试仍开启、保存的端口有效。不能把该设备的一次成功解释为所有
6.1 系统、所有广告都已验证。

调试时曾验证 AbilityDelegator 的命令路线，但命令白名单、测试观察对象寿命、文件读取
权限使其不适合作为此设备的布局回传通道。最终不采用该路线，也不保留额外常驻 aa 进程，
监督脚本沿用 0.9.54 压力测试版本。

参考：[系统命令接口文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-test-kit/js-apis-inner-application-abilityDelegator.md)。
本地 SDK 的 `@ohos.uitest.d.ts` 将 `Driver.dumpLayout` 标为 since 26.0.0。

## 持久化诊断

此前 `SystemExitStore` 只保存错误码；普通 Error 没有 code，最终变成 `undefined`。
具体异常仅在当前工作历史与 hilog 中，重启后可能丢失。本轮已增加：

- 独立 `worker-failures.json`，最近 20 次终止错误，重启后继续保留。
- 异常名称、原始消息、堆栈、发生阶段及时间，工作 PID、会话 token、恢复次数、API 版本、
  应用包名、心跳与 RPC 时间；不记录调试密钥或完整页面内容。
- 消息最多 2000 字符、堆栈最多 6000 字符，仅在终止错误时写入，不按扫描帧刷日志。
- 无错误码时保存 `NO_CODE`；普通程序异常不再统一宣称为 UiTest 接口错误。
- 系统退出记录按 PID、token、会话开始时间关联对应错误。导出 schemaVersion=3，包含
  `workerFailures`、系统原始退出信息和监督时间线。
- 本机通信失败保留原始错误原因；一次状态文件写入失败后不由心跳定时器重复刷同一错误。

上一轮 00:29 的旧异常无法由新增日志追溯还原，不宣称已经确定它的根因。

## 真机记录

首次无规则进入驾校一点通：自动学习 S03，按现有设置自动启用；发现前台后 1421 ms
发出点击，输入调用 124 ms，点击前布局读取 360 ms、读取后复核 54 ms。随后在同一应用
连续两次观察到目标与原位置广告标记消失。此轮无 OCR、无人工启用或点击。

最终包在故障恢复后再次打开同一应用，已有规则于发现前台后 757 ms 发出点击（识别
397 ms、复核 355 ms，其中布局读取 323 ms），输入调用 122 ms，随后确认广告消失。再次从桌面重新打开，799 ms 发出点击、输入调用 115 ms，亦确认广告消失。

另在最终包主动注入普通 Error（仅本测试版本、匹配当前会话 token 的测试钩子）：记录
`NO_CODE / Error / QuietStart diagnostic capture probe`，阶段 `session-control`，堆栈包含
SupervisionStressProbe 与 SkipWorker 的代码行。旧 PID 47061 结束，监督恢复新 PID 47814；
恢复后错误文件仍保留该记录，系统退出记录也关联到同一异常。这是受控验证，不是自然崩溃。

验证：构建与内外包校验通过；266 项现有工作模块回归（含旧路径用例）、41 项本机通道/
布局/诊断测试通过。真机为 USB 连接；命令由手机本机连接执行，未用电脑发送广告点击。
本轮未做新的拔线、长时间待机或内存压力验证，不将一次恢复解释为长期保活已彻底解决。
原始诊断和签名包保存在本地忽略目录，未推送或发布。
