# 应用名称与安装状态修复（0.9.59-test）

## 根因

- 本机名称补全仅使用 `bm dump -n <bundle> -l`。卓易通虚拟包不在原生 BMS 列表中，因此该查询失败。
- 旧桌面解析仅支持 `Container_AppIcon_Image_`。本次 HarmonyOS 6.1 真机使用 `AppIconCommonView_` 与独立的 `AppNameLite_text_<bundle>_<token>`，中文名称被漏掉。
- 应用管理合并历史访问、配置和规则引用，没有安装状态，因此删除历史行也可能被规则重新加入。

## 改动

- 兼容桌面的 `AppNameLite_text_`、`AppName_text_` 以及原有格式。仅接受系统桌面、可见控件、精确包名关联的文字，保留用户备注名优先级。
- 卓易通名称不再反复查询原生 BMS。其他缺失名称每个工作会话最多尝试三次，间隔至少一分钟。桌面名称采集仍是每次返回桌面的一次控件树读取，不截图、不定时轮询。
- 进入应用页、返回应用页前台或手动刷新时，通过本机已授权连接查询原生安装列表。自动刷新间隔至少 30 秒，并合并并发请求；强化学习前强制检查。
- 仅对曾由完整原生目录确认的应用判定卸载。列表损坏、连接失败、缺少轻启自身记录、过期返回或较新的前台访问不会触发错误移除。
- 卸载应用移出管理列表，保留规则和名称；原生应用重装后恢复，手动移出的应用在下一次被观察到前台时恢复。
- 原生目录缺少卓易通应用不代表卸载。卓易通两种桌面启动入口都返回匹配失败时，将其入口标记为不可用并移出列表，保留诊断和规则；实际再次打开后恢复。网络、授权或普通启动错误不用于判定卸载。
- 管理页增加“移出应用列表”。忽略卓易通宿主 `com.huawei.shell_assistant` 和 Android 权限控制器，避免将它们当作独立用户应用。

## 验证

设备：Pura 70 Pro，OpenHarmony 6.1.1.120 / API 24。API 26 未在本次连接中真机复测，保留旧格式解析回归。

- 构建与内外模块重签成功；覆盖安装 0.9.59-test，轻启自行安装工作模块并重新在线。
- 安装后真实桌面自动补全：十六番旅行、网易严选、网易云音乐；未通过电脑写入名称缓存。
- 应用页通过手机自己的无线调试连接成功同步原生安装目录。
- 真机将十六番旅行移出列表，确认不再展示；重新打开后状态自动恢复。没有卸载用户应用。
- 19 条既有规则全部保留，自动跳过和学习开关开启。
- 546 项自动测试通过，包含旧/新桌面格式、原生卸载及重装、虚拟包保留、失败/过期目录、备注及规则保留、前台恢复等。

## 边界

系统没有通过本次可用原生目录提供完整卓易通安装清单。因此无法在从未尝试启动的情况下，可靠批量判定所有旧卓易通条目是否已卸载。桌面名称需要相应图标在返回桌面时可见；隐藏文件夹或未显示页面不能凭空获得名称。手动“移出列表”用于这些历史失效条目的整理。规则从不随清理删除。
