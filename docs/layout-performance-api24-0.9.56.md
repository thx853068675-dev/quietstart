# API 24 布局读取与点击复核优化（0.9.56-test）

设备为 Pura 70 Pro，OpenHarmony 6.1.1.120 / API 24。2026-09-16 真机测试，USB 保持连接；布局仍由轻启自身通过 127.0.0.1 无线调试通道获取。没有做本版本的拔线测试或长时间能耗测试。

## 改动

- 同一工作会话复用已认证的只读布局连接，每次请求分配新 HDC 通道编号。迟到的旧数据不会满足新请求；拒绝并发读取。
- 空闲 15 秒关闭连接，下次读取重新建立；单次请求上限 5 秒、响应上限 4 MiB。工作会话结束时主动释放连接。
- 分包只做末尾结束标志检查，收齐后一次合并、一次 UTF-8 解码，避免反复复制并解码全部已有内容。
- 已选规则的点击复核不再执行无广告页面分类，也不重新发现未获批准的结构候选。保留所有节点用于遮挡、禁用状态、父容器和目标几何检查。
- 新增 QuietStartLayout 分段日志：身份加载、TCP 建连、认证、命令发送、首包、收齐、字节数及是否复用。日志不包含布局正文或密钥。
- API 26 继续使用原生 Driver.dumpLayout；通用点击复核的重复分析也被移除。

双快照目标和窗口一致性检查仍保留；读取 700 毫秒、读取后复核 300 毫秒、总计 800 毫秒的时限均未放宽。没有将旧坐标当成新快照，也没有把 OCR 引入已选按钮点击复核。

## 分阶段真机结果

上轮 0.9.55-test 用户启动测试中，12306 单次复核布局读取 780 / 791 毫秒、读取后复核 251 / 259 毫秒，因超时未点击。

只做连接复用时，驾校一点通连续三轮点击并确认消失；复核读取 318、261、246 毫秒。较大布局仍有明显的回传处理耗时。

加入一次性解码后，对 170–200 KB 的布局采样：首包到收齐的中位数由 186 毫秒（8 份）降至 33 毫秒（31 份），读取总耗时中位数由 704.5 毫秒降至 545 毫秒。它们是分阶段、相近大小的实际页面样本，不是固定页面随机 A/B，不能等同于全部场景提速比例。

此阶段 12306 又出现读取 496 毫秒、读取后复核 315 毫秒而被取消的样本，因此继续缩减点击复核中的重复分析。

最终版 12306 已完成一次点击并连续两次确认目标及广告标记消失：发现前台到发起点击 1487 毫秒；匹配 819 毫秒；复核 656 毫秒（读取 468、读取后 184）；输入调用 123 毫秒。其他未出现可识别目标的启动不计为“跳过成功”。

最终版驾校一点通三轮均完成点击并确认消失，前台发现到发起点击分别 1709、1239、1145 毫秒；复核读取分别 325、285、280 毫秒，读取后处理 57、50、54 毫秒。首轮先读到启动画面的 3 个控件，说明启动过程和首次读取仍存在波动，不能宣称所有场景都低于 1 秒。

这些数值不含按下桌面图标到检测到前台的时间，也不包含点击后的消失核对。API 24 仍有执行系统布局命令的开销，不能宣称达到 API 26 的速度。

空闲重连也已真机验证：回到桌面等待 18 秒后，下一次读取记录 reused=false，重新建立连接；随后各帧 reused=true。该轮恰好出现驾校一点通新样式“跳过4”，成功追加规则、按现有设置启用、点击并确认消失（发现前台至点击 2129 毫秒，包含新样式两帧学习）。这同时验证了收窄执行复核不会禁用新样式学习。

该次冷连接的身份加载到发送命令约 47 毫秒，说明重复连接确实有开销，但系统布局导出以及原先重复解码、重复分类才是更大的瓶颈。不能把全部收益归因于连接复用。

最终工作会话记录 5 次点击、5 次确认消失，恢复次数为 0，未新增终止异常。安装/重新激活产生的进程替换未计入运行闪退。

- 31 项布局及本机连接测试通过，覆盖旧通道迟到响应、连续请求、并发拒绝、超时、端口变化、空闲关闭、UTF-8/结束标志跨包及响应上限。
- 14 项会话健康及异常诊断测试通过。
- 单包构建、内外模块重签及封装校验通过；真机由轻启更新工作模块并恢复在线。

本轮性能优化没有修改爱奇艺 OCR 兜底判断；此前系统文字识别服务异常仍属于单独问题。新增诊断日志与原有 worker-failures 保留机制继续工作。
