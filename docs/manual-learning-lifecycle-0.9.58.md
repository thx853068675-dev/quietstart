# 0.9.58 测试记录：启动、手动学习与后台恢复

设备：HBN-AL00，OpenHarmony 6.1.1.120，API 24。版本为本地测试包，尚未发布。

## 已确认的启动问题

原先使用隐式 home action 启动。驾校一点通声明的 home skill 还要求 URI，命令会返回 10103101，或出现“暂无可用打开方式”。桌面有图标不代表这条隐式调用能匹配入口。

现在先读取目标包声明的主模块、导出 PAGE ability，按真实入口显式启动；卓易通虚拟包不在原生 bundle 列表时，使用系统虚拟包启动路由。命令通过已经授权的本机 loopback HDC 连接执行，关闭连接后不改变当前工作会话。没有扫描桌面或依赖文件夹位置，也没有假定所有应用都叫 EntryAbility。

已在设备上验证驾校一点通从强化学习按钮自动打开；卓易通网易严选的系统启动路由可用。也已从网易严选的强化学习按钮自动打开虚拟应用并见到广告弹窗；完整的手指点击后保存流程仍需单独验收。

## 手动学习

用户示范对应到唯一、紧凑的实际按钮后直接追加并启用，保留旧规则；无需等待两次目标消失。后续继续核对当前应用、样式、相对位置、唯一性和遮挡，不直接重放旧坐标。倒计时数字变化不再造成手动规则失配，明确“跳过／关闭”语义相同时允许开发者 ID 变化。

API 24 的事件监听与 CLI 布局读取可能争用 AAMS。手动学习期间不启动第二个 CLI 布局客户端，先建立原生事件连接，再使用实际系统点击事件的小控件元数据与当前窗口核对。未收到事件时明确失败，不虚构手动规则。监听在等待目标应用时也续订。

## 第一轮压力结果

30 次启动请求覆盖 10 个应用，22 次在每轮采样结束时确认目标前台；恢复期间部分请求被恢复界面打断，不能把 30 次都称作成功打开。前 12 次自动跳过开关未开启，只能作为启动和存活样本。后续共记录 7 次点击、4 次目标消失确认；另有 3 次新样式学习。点击及消失是不同指标。

同时施加有上限的真实匿名内存压力：峰值压力进程 RSS 3,059,148 KiB（约 2.92 GiB），采样最小 MemAvailable 1,346,560 KiB，最高电池温度 37°C。未修改系统回收策略，也未主动向轻启发送杀进程信号。

| 事件 | 证据 | 恢复 |

| PID 25246 于 1789502239935 被回收 | 启动原因 7、LowMemoryKill；系统退出详情保留 PID/RSS/时间 | 1789502266000 健康检查恢复，约 26 秒 |
| PID 36823 于 1789502277739 再次被回收 | 系统 memmgr/AppMS 明确 LowMemoryKill、信号 9；启动参数却返回原因 2 且详情空 | 1789502313000 健康检查恢复，约 35 秒 |

监督 PID 25328 全程存活，最终工作 PID 39754、RPC 年龄 2 秒；压力进程 RSS 回到 0。第一次回收前工作进程已在后台调度组，第二次系统记录回收优先级为 1000。持续压力会导致恢复后再次被回收，不能承诺永久保活。第一轮中有一次短暂返回轻启开启开关，因此不是完全不干预的长期后台试验。

## 退出诊断补充

启动参数可能漏掉真实系统原因。增加 HiAppEvent APP_KILLED / APP_CRASH / APP_FREEZE 订阅，最多本地保留 40 条去重元数据，随诊断导出；保留启动原因的原始值，不覆盖主动停止判断。新包已实际收到 APP_KILLED 的升级事件。

依据：[华为系统应用终止事件订阅](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/hiappevent-watcher-app-killed-events-arkts)。回调可能在重新打开后才到达，不把事件订阅当作保活能力。

## API 26 边界

已确认按钮优先匹配、同一新鲜完整布局复用等纯处理优化共同使用。API 26 仍使用原生 dumpLayout，保留读取 700 ms、读取后复核 300 ms、读取及复核总计 800 ms 上限；API 24 的 CLI 路径和两帧学习复用不移植到 API 26。后续已补做 API 26 真机对照，并修正复核时限，见 [API 26 验证](api26-validation-0.9.58.md)。

## 第二轮与最后验收

新诊断包上再执行 30 次循环启动，25 次在每轮末尾确认目标前台，记录 13 次点击、11 次消失确认。全程自动跳过开启，测试中未手动进入轻启。两轮中的未到达次数不能直接视为启动失败，包含恢复界面与目标切换期间的采样。

第二轮峰值压力 RSS 3,174,812 KiB，采样最小 MemAvailable 1,474,560 KiB，最高电池温度 38°C。再次发生两次系统内存回收：时间分别为 1789503101445、1789503132940；两个 APP_KILLED / LowMemoryKill 都已由轻启自身订阅接收并持久化。这台 6.1 的事件未带 PID/detail，保留缺失信息，不填造。最终工作 PID 55295，监督 PID 45586，RPC 年龄 3 秒，压力进程 RSS 0。两轮四次回收均自动恢复。

最后强化学习验证：驾校一点通成功打开但未再出现广告；网易严选成功打开，模拟点击关闭了广告，但未收到系统 COMPONENT_CLICKED 回调，因此不能认定完整手动学习已通过。额外 uiRecord 只做了独立可行性探测，未并入产品；该机需要 SIGKILL 才能可靠终止，已确认探测进程及 record.csv 清理完毕。

退出强化学习后，补测驾校一点通、虎扑、微博三次冷启动，全部到达前台；驾校一点通与微博完成点击及消失确认。会话 PID 未改变。

离线回归：537 项通过。源码与测试包保留在本地，尚未发布。API 26 后续已真机验证；真实手指关闭广告后保存规则仍未完成验收。
