# 0.9.60-test：恢复边界与连接体验

## 最终策略

- 明确的系统 `User Request`（退出枚举、顶层消息或退出详情）和应用内主动结束连接不恢复。经本轮令牌、PID、时间及成功终止命令核实的守护重建不视为用户终止。
- 其他退出原因，包括升级、崩溃、资源管控、未知原因，均允许尝试恢复。
- 连续失败最多重试 4 次，间隔 5、15、30、60 秒。最后一次仍失败则退出守护并提示重新连接；每次启动仍保留原有 45 秒启动验证宽限，不因命令发出就判定成功。
- 稳定健康 60 秒重置连续失败计数。累计恢复次数只用于诊断，因此后续故障仍可获得新的四次预算；工作模块入口同步解除旧的“累计超过三次即拒绝”限制。
- 退避期间每 5 秒检查主动停止/会话替换。命令执行失败也计入相同上限。休眠且进程仍在时不因暂停心跳重启，不主动点亮屏幕。
- 保留退出原始原因和恢复次数。预算耗尽时自身的终止命令可能返回 User Request，界面仍显示“四次恢复失败”，不误写为用户主动清理。

## 本机连接

提交端口后进入概览的连接进度状态。应用/工作模块更新重开界面后恢复同一进度；连接期间每 250 毫秒只读取小型连接状态文件，规则和应用目录仍保持原有刷新频率。仅收到新会话有效心跳和 RPC 后显示在线；旧会话及仅命令发送成功不能被当作连接成功。失败时返回连接表单，保留端口并显示具体错误。

新本机连接经过认证、准备好模块并准备启动会话时开启自动跳过；不改动规则批准状态。普通自动恢复不执行该启用步骤，所以用户手动关闭的开关不会被恢复流程重新打开。连接成功/失败后和页面离开前台时停止快速状态轮询。新连接同时清理上一次停止提示。

## 验证

- 构建及单包内外重签通过；Pura 70 Pro / HarmonyOS 6.1 / API 24 覆盖安装成功，工作模块由轻启自行更新，安装收据哈希与最终包一致。
- 547 项应用回归通过；最后的提示清理和预算诊断调整另重跑 30 项连接测试、17 项会话诊断测试，均通过。
- 11 项真实守护脚本状态机测试通过（用虚拟时钟和模拟系统命令执行同一生产脚本）：四次精确退避、耗尽终止、退避中停止、User Request 中断、健康一分钟重置预算、命令失败、休眠、互斥等。
- 最终包真机注入工作模块异常，约 33 秒内观察到新会话、新鲜 RPC 与健康状态。电脑只注入故障和采样，未发送恢复启动命令。
- 异常前手动关闭自动跳过，恢复后仍为关闭；主动重新连接则默认开启。
- 连接中与成功后的真实屏幕已检查，进度显示在概览；成功后为在线，未要求再点击“开启自动跳过”。

真实手机验证覆盖一次异常恢复与重复本机连接。四次耗尽和全部系统原因组合是自动测试覆盖；未在本轮进行手机四次连续破坏、拔线或长时间锁屏测试。若独立监督也被系统结束，或者手机重启/调试权限撤销，仍可能需要重新连接。
