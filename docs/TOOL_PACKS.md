# 工具包制作教程

> 核对日期：2026-11-16。文档按轻启 **1.3.0 引擎线**整理；公开安装包是否包含某个接口，以实际安装包的内部版本号和更新说明为准，不能只看显示版本。
>
> 本文讲如何设计、编写、校验和分发工具包。所有声明式字段的类型、取值与默认行为见[能力接口字段手册](CAPABILITY_INTERFACE.md)；签名脚本工具包的 manifest、`policy.json` 和方法门禁见[宿主 API 手册](HOST_API.md)。
>
> 本文只用示例应用与通用页面文案介绍配置方法，不提供具体应用的配置合集。

轻启支持两种工具包：

- **声明式 JSON**：写清楚适用应用、触发时机、目标控件、动作和成功判据。普通规则路径不执行 JavaScript，开销更小。
- **签名脚本包**：声明式表达不了有状态分支、循环、重试、冷却、滚动查找或跨任务接续时使用。脚本只在受限运行时内执行，不能扩大引擎权限。

无论哪种，引擎都保留读页、窗口与前台核对、几何与遮挡、输入租约、动作账本、取消和资源约束；工具包只描述业务。

---

## 1. 先确定包要解决什么

写配置前，用普通语言列出五件事：

1. **入口**：用户进入哪个应用、哪个页面？仅打开应用就运行，还是要用户主动点击某个入口？
2. **目标**：页面上哪个控件？同一页是否有同名按钮？需要什么依据才能确认它是目标？
3. **动作**：点击、返回、滑动还是输入？动作发出后页面应该发生什么？
4. **结束**：怎样确认这一项完成？哪些情况应停止而不是继续重试？
5. **边界**：哪些页面、弹窗、登录/支付/授权场景必须拒绝或交给用户？

先做单步包，确认目标范围和结果判据，再扩成多步。需要一份文件管理多个独立任务时，使用 `schema: 3`；每个 `tasks[]` 子任务仍是一份完整的 `schema: 2` 文档。

**三条原则：**

1. 工具包不能扩大引擎权限。唯一目标、可见/可用/可点击、几何上下界、前台归属、动作前后复核和资源限制都在引擎里，文档只能收紧。
2. 引擎不替包决定业务。任务顺序、分支、循环、重试、冷却和完成判定由包描述或由包内脚本决定。
3. 未知字段、未知能力和未声明目标一律拒绝，不会“忽略后继续”。

## 2. 写出第一份声明式包

把下例保存为 UTF-8 编码的 `my-confirm.task.json`。把 `com.example.app` 换成真实包名，把页面文字换成实际内容。

```json
{
  "schema": 2,
  "id": "example.confirm-dialog",
  "name": "确认提示框",
  "version": 1,
  "appliesTo": ["com.example.app"],
  "when": { "trigger": "app-foreground", "windowMs": 12000 },
  "defaults": {
    "limit": { "maxWidth": 0.5, "maxHeight": 0.16, "maxArea": 0.06 }
  },
  "steps": [
    {
      "find": {
        "by": "text",
        "match": ["我知道了"],
        "sameParentText": ["提示标题"]
      },
      "do": { "capability": "click" },
      "expect": { "result": "gone", "settleMs": 5000, "samples": 2 }
    }
  ]
}
```

这份包的含义：

- `appliesTo` 限定应用，还要和轻启内该应用的启用开关同时满足；写了它不会替用户勾选应用。
- `when.windowMs` 从应用进入前台开始计时，12 秒内才观察目标。
- `find.sameParentText` 要求“我知道了”和“提示标题”是同一父容器的直接子节点，避免点到别的卡片上的同名按钮。
- `defaults.limit` 限制目标尺寸占窗口的比例。**引擎要求每一步都能解析出完整的 `maxWidth` / `maxHeight` / `maxArea`**；最小包也必须写 `defaults.limit`，或在该步 `find.limit` 里写全。只写一半或不写，即使本地校验器没报，导入时也会被拒绝。
- `expect` 要求点击后目标连续两次从新读取的页面里消失。点击已发出和结果已确认是两件事。

`id` 是稳定身份，更新时保持不变；`version` 每次发布新内容递增。同一 `id` 再次导入会更新该包。

### 2.1 给导入者写使用说明

顶层可加 `usage` 字符串，1–400 字符，不能全是空白。导入成功后弹一次说明，之后可在工具包详情查看。它只展示文字，不改变触发条件。

```json
"usage": "在目标应用的「我的」页，亲自点击活动入口。保持轻启的本机连接和自动执行开启。"
```

### 2.2 声明最低轻启版本

```json
"minAppVersionCode": 130001,
"minAppVersionName": "1.3.0"
```

比较只使用 `minAppVersionCode`；`minAppVersionName` 只用于提示，填写时必须同时有版本号。版本不足时，导入、订阅更新、启用和执行会提示升级并保留旧包和开关。合成包及其子任务按最高要求检查。

## 3. 触发、目标、依据和动作

### 3.1 触发

| 场景 | 写法 | 执行范围 |
|---|---|---|
| 只在打开应用后的短时间看 | `{"trigger":"app-foreground","windowMs":12000}` | 观察 1–30 秒 |
| 只在指定页面看 | `{"trigger":"page-foreground","pagePath":["TargetPage"],"windowMs":6000}` | 前台进入后，还要命中页面路径 |
| 每次进入新页面再看 | `{"trigger":"page-visit","windowMs":6000}` | 每页重新计时；读不到页面路径则不执行 |
| 任务出现时间不确定 | `{"trigger":"app-foreground","lifetime":"foreground"}` | 保持前台期间观察；单步发出动作后停止 |

`lifetime` 与 `windowMs` 只能选一个。多步任务即使使用前台常驻，仍受 `defaults.totalMs` 的整轮上限约束。

### 3.2 目标

| 字段 | 说明 |
|---|---|
| `find.by` | 识别路径：`text` / `desc` / `image` / `structure`；不写默认 `text` |
| `find.match` | 必填，目标形式白名单，非空 |
| `find.explicit` | `true` 表示文字本身就是明确动作；`false` 表示必须另有 `need` |
| `find.actions` | 显式动作词；和 `explicit` 只能声明一个，且每项必须已在 `match` 里 |
| `find.glyph` | 字形兜底（如 `×`） |
| `find.idHints` | `[[id 词根, 标签], …]`，认无文字控件 |
| `find.sameParentText` | 目标和指定文字必须是同一父容器的直接子节点 |
| `find.limit` | 只能比 `defaults.limit` 更小，不能放宽 |

`need` 提供识别依据：`evidence.text` / `evidence.id` 在发现新规则时使用；`visibleText` / `absentText` 在每次执行前都检查当前可见画面。`deny.context` 是反例语境，只能加不能减，引擎兜底表始终生效。

### 3.3 动作

| `do.capability` | 参数 | 适用 |
|---|---|---|
| `click` | 无 | 目标可点（最常用） |
| `back` | 无 | 关闭按钮很难点准；目标只需“存在”，发返回键 |
| `swipe` | `from` / `to` / 可选 `speed` | 下拉关闭类浮层；坐标是归一化 0–1，不写像素 |
| `input` | `text`（1–64 字符） | 自动填词；判据不得是 `gone` |
| `wait` | `ms`（50–30000） | 多步序列里的纯等待步；只等待，不识别、不动作、不判据 |

后四种动作没有“目标”，由**包级授权**：启用一个包 = 授权它声明的动作。目标闸门与动作后复核仍然全部执行。`wait` 步不得带 `find` / `need` / `deny` / `expect`，且第一步不能是 `wait`。

### 3.4 判据

| `expect.result` | 成立条件 | 用在哪 |
|---|---|---|
| 不写 / `gone` | 目标消失（动作后连续 `samples` 帧都找不到） | 点击 / 返回 / 滑动（默认） |
| `appeared` | 期望的文字出现（需 `match`） | 点完出现某个东西 |
| `text-changed` | 目标处文字变了（与学习规则时记录的文字比） | `input`（输入框不会消失） |

复核参数：`settleMs` 500–60000（缺省 5000）；`samples` 2–4（缺省 2）。取值优先级：该步 `expect` → 文档级 `defaults` → 引擎缺省。

判据**永远不会默认为真**：树读不到、目标找不到、基线空缺、无法判定，一律记“未确认”，不算满足。`timeout` 没有实现，写了会被拒。

## 4. 多步、重复和合成包

`steps` 1–8 步，按序执行；每一步独立过全部闸门，上一步未确认成功，序列立即停止并如实记账。

- `defaults.totalMs` 1000–240000，缺省 30000，从第 1 步动作发出时起算（`wait` 也计入），到点立即停止。
- 前台应用变了、会话结束、应用被暂停，立即停止。
- `repeat` 只用于 `app-foreground` + `lifetime: "foreground"` + 至少两步的包；`maxCycles` 2–300、`cooldownMs` 500–10000、`idleMs` 3000–60000。一轮必须每步都复核成功才重启。
- `steps[].skipWhen` 只在多步流程的后续步骤使用，连续两次新页面分别满足“指定文字全部可见”和“指定文字全部不可见”才跳过该步；`stopRepeat: true` 只能写在最后一步。

```json
"defaults": { "totalMs": 8000 },
"steps": [
  { "find": { "match": ["关闭"] }, "do": { "capability": "click" }, "expect": { "result": "gone" } },
  { "find": { "match": ["返回"] }, "do": { "capability": "back" }, "expect": { "result": "gone" } }
]
```

### 4.1 `schema: 3` 合成包

一份文件管理多条流程、一个启用开关。`tasks` 里通常是多个完整 `schema: 2` 文档，所有 ID 唯一，子任务 `appliesTo` 必须与外层一致；`appliesTo` 必须是非空白名单。

入口方式必须且只能选一个：

| 字段 | 用途 |
|---|---|
| `entryAfterClick` | 用户亲自点击入口后，目标页标识从无到有才开始 |
| `entryOnTap` | 1–4 个互不重复的入口文字，真实点击后唤醒 |
| `entryOnForeground: true` | 应用首次进入前台即开始 |
| `entryAfterClickAny` | 同一入口可能打开任务页或直接打开另一页 |
| `entryClickTargets` | 精确控件入口声明（需较新引擎） |

常用编排字段按需声明，不要把所有字段都塞进一份包：

| 场景 | 字段 | 要点 |
|---|---|---|
| 每日首次签到 | `entryOnForeground: true` + `oncePerDay: true` + `dailyCheckIn` | 三者同时出现；`tasks` 为空；领取并回到首页都确认才记当天完成 |
| 视频奖励循环 | `rewardVideo` | 声明识别文字、区域、关闭标记、终止文字；按实际状态推进，不按固定秒数 |
| 安装/打开任务 | `rewardInstall` | 要求 `entryAfterClick`；按当前列表按钮判断可做；完成确认后才计数/清理 |
| 分阶段区域任务 | `rewardStages` | `install` / `open` / `video` 分段；每段独立次数和刷新上限 |
| 跳转落地页停留并返回 | `landingVisit` | 提示、按钮区域、停留、确认/取消策略、返回方式都在包内声明 |
| 普通多步入口的定时插队 | `taskSchedule` | 组、锚点任务、间隔、检查点、恢复任务；不创建后台定时器 |
| 找不到目标时的有限搜索 | `missingTargetScroll` | 页面文字、反例、方向、区域、速度；只在入口激活且仍在任务页时用 |
| 关闭本包 OCR | `ocrEnabled: false` | 只影响本包及子任务；原生控件和复核继续 |

合成包不是“字段越多越强”：只声明实际流程需要的部分。未使用或互相冲突的工作流字段会被拒绝，或产生错误分支。

### 4.2 工具包和规则是两层

**导入成功 ≠ 会点击。** 工具包是静态配置：词表、动作授权、判据。规则是运行时学到的实例：哪个应用的哪个控件（id + 几何）。引擎的点击来自已启用的规则，工具包本身不直接点击。

首次遇到目标时的链路：

1. 前台进入应用，引擎先按已启用规则匹配。
2. 未命中时，才按包的词表发现新候选、学出一条新规则——默认“待确认”。
3. 到「规则 → 待确认」核对文字与位置，确认后启用；预先开启“规则自动启用”可让有明确依据的新规则直接启用。
4. 再次遇到相同样式时，规则直接命中 → 执行动作 → 按判据复核。

“学习新规则”“自动发现应用”“规则自动启用”三个开关决定链路是否走通。都不开时，已启用的旧规则照常生效。

词表是规则的白名单：规则的 label 与 marker 必须被同一个包认领。`find.match` 写进 label，`need.evidence.text` 写进 marker，`targetLabel` / `markerEvidenceLabel` 用于树里读不到文字的情况，`appliesTo` 决定不在名单里的应用不学习、也不生效。从 `find.match` 删词会让对应规则休眠（保留在磁盘上），加回或重新启用原包即恢复。

## 5. 签名脚本工具包

当声明式表达不了有状态流程时，使用 `schema: 5` 签名脚本包。它仍然受当前应用、窗口、目标、几何、可见性、输入租约、动作账本和资源预算约束，不是“权限更大的声明包”。

最小签名载荷包含：

```text
manifest.json   身份、profile、能力、触发、预算
rules.json      原声明式规则或 actor 元数据
policy.json     查询程序 / actor 程序
main.mjs        业务脚本入口
migrate.mjs     必填文件；无迁移时返回原状态
config.json     可选参数声明
LICENSES.txt    依赖与许可说明
```

关键取舍：

- `task-intent/1`：一次事件走一小步；每个事件最多一次读页、一次物理输入；长期等待用 `next.at`；完成必须引用宿主 `completionProof`。
- `task-actor/1`：前台会话内常驻，`actor.next()` 等真实事件；每回合最多一次物理输入；状态写声明文件。
- `companion/1`：独立助手端口，文件和网络能力不与普通任务混用。
- 脚本不能调用未注册方法；能力是“实现 ∩ profile ∩ 签名声明 ∩ 发布者授权 ∩ 当前会话条件”的交集。
- 旧 `legacy-task-policy/1` 只作兼容，不用于新包；现代包失败不会回退旧业务 Worker。

签名、授权、manifest、`policy.json`、`main.mjs` 和宿主 API 的完整说明见[宿主 API 手册](HOST_API.md)。脚本工具包要求 **API 26**，不是所有设备都能使用；发布前先确认目标设备与安装包都满足要求。

## 6. 校验、导入和更新

1. 保存为 UTF-8 JSON；文件可以用 `.task.json`，也可以把同样的 JSON 内容存为 `.txt`。确保没有注释、尾逗号和重复键。未知字段会使整份文档被拒。
2. 如持有轻启源码仓，运行 `node tools/task-document.cjs 文件名.task.json` 做本地校验；它报告字段名、范围、动作与判据组合、子任务应用范围等问题。没有源码仓也可以在轻启导入页得到拒绝原因。
3. 在轻启「工具包 → 导入」选择 JSON 文件或粘贴全文。导入成功后核对名称、版本、启用状态和任务数量。
4. 在「应用」中启用目标应用；首次发现目标后，在「规则」页确认对应规则。导入工具包和批准规则是不同步骤。
5. 查看「运行记录」中的“发现目标、发送动作、确认生效、未确认/停止”四类结果。修改词表、页面条件或流程后递增版本，重新导入并逐项核对。
6. 分发时提供单份 JSON、适用的轻启版本、适用应用包名、触发入口和版本更新说明。不要把账号、原始页面树、录屏或个人数据写进工具包。

支持最低版本检查的安装包会在版本不足时提示升级；替换或订阅更新不兼容时，原正文、更新时间和启用状态保留。旧客户端无法通过配置自行补上该提示。版本名用于展示，比较只看内部版本码；复合文档按各部分要求的最高值处理。

### 6.1 订阅发布

订阅就是一条 HTTPS 链接，返回单份工具包 JSON 或 `index.json` 清单。清单里的 `version` 必须与正文一致；同 id/version 的不同内容必须递增版本。生成清单后把整个目录挂到静态托管即可。清单格式、托管和更新语义以发布页和工具包订阅说明为准。

## 7. 常见问题

| 现象 | 先查什么 |
|---|---|
| 导入被拒：`含未知字段` | 字段名写错，或抄了旧格式字段；删掉未知字段 |
| 导入被拒：`find.limit 无法解析` | 缺 `defaults.limit`，或三个值没有写全；补全后再导入 |
| 导入成功但不点击 | 工具包是否启用；目标应用是否勾选；规则是否还在“待确认”；词表是否被改掉导致规则休眠 |
| 点击后不确认 | 判据是否真的成立；`settleMs` / `samples` 是否足够；页面是否被弹窗遮挡 |
| 输入后判据失败 | `input` 不能用 `gone`，改用 `text-changed` 或 `appeared` |
| 多步流程中途停止 | 上一步是否未确认；前台是否切换；`totalMs` 是否到点；应用是否被暂停 |
| 合成包只执行一部分 | 入口是否真实触发；子任务 `appliesTo` 是否与外层一致；多个包是否争用同一入口 |
| 规则页“变空” | 是否从 `find.match` 删了词、停用或删除了包；规则可能只是休眠 |
| 版本不足 | 升级轻启，或降低包的最低版本要求；不要用旧客户端强导 |

调试时先看运行记录/诊断的阶段：触发 → 范围 → 候选 → 证据 → 许可 → 几何 → 输入 → 确认。不要把“没点到”一概归为词表问题。

## 8. 发布前检查

- 包能导入，`id` / `version` / `name` / `appliesTo` 一致；版本号已递增。
- 每一步都有完整几何上限（`defaults.limit` 或该步 `find.limit`）。
- 目标词、依据词、反例词与实际页面一致；没有把具体应用的词写进通用包。
- 动作有对应授权；输入判据不是 `gone`；多步总时长足够但不过长。
