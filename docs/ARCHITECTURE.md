# 架构与识别流程

- `entry/src/main/ets/pages`：ArkUI 页面。
- `entry/src/main/ets/core`：设置、规则、运行记录、本机 HDC 连接及本地识别条件。
- `entry/src/ohosTest/ets/worker`：设备端观察、学习、点击与消失验证。
- `tests`：执行实际模块逻辑的离线回归与脱敏结构样本。
- `tools/community`：社区数据下载、转换与回放，不参与手机运行。

## 处理顺序

1. 读取前台窗口，确定应用及本次观察过程，检查暂停与工作范围。
2. 优先匹配已批准按钮：应用、文字或结构、类型和当前位置。无需再次验证旧广告文案或运行 OCR。
3. 未匹配时发现新候选：文字、描述、ID、倒计时和控件关系共同提供证据。结构经验由 `StructuralExperience.ets` 维护。
4. 控件证据不足且满足候选条件时才进行有预算的本机 OCR。新样式稳定后保存；默认待确认，可选自动启用只作用于首次发现。
5. 点击前独立核对当前窗口、目标、坐标新鲜度、遮挡及开关；不会直接按历史坐标盲点。
6. 发送后单独观察目标是否消失，将各事件归入同一过程时间线。

社区经验目前包含计时文字与图片重叠、相邻计时/图片和明确开屏容器内的角落无文字 View。它们是带约束的结构关系，不能泛化成“所有角落叉号都点击”。

识别条件随应用内置并可手动编辑；它们不会赋予个人广告规则点击批准。0.9.41 移除云订阅与 HTTP 客户端，升级保留现有生效条件并清理旧订阅元数据。

## 单包安装

主 HAP 的 rawfile 包含同签名配置构建的工作模块与 SHA-256 清单。0.9.46 起，准备阶段经已授权的 loopback HDC 会话传输并校验数据，安装交给独立进程：即使 `bm` 结束轻启进程，安装任务仍可完成并保存回执，再通过会话标记重新打开轻启。

恢复阶段重新连接本机 HDC，同时核验回执摘要与系统模块版本，再保存应用内回执并启动 UiTest，最后以新心跳与 RPC 响应确认在线。恢复失败不会自动循环安装；手动重试会先检查已完成的结果。安装命令最多等待 45 秒，缺失恢复回调也有超时状态，不会无限显示安装中。

系统 `bm` 可能在失败时返回退出码 0，且直接重定向输出到普通文件会丢失内容。因此使用管道收集输出，单独保留超时退出码，并要求明确成功文本、无失败文本及系统模块核验全部通过。应用不从服务器下载代码或模块。

## 后台与会话恢复

主界面和 TestRunner / SkipWorker 共用应用进程，UiTest daemon 独立运行。0.9.52 本机连接会另行派生独立 shell 监督任务；激活用的 HDC TCP 会话随后关闭。监督每约 5 秒读取小型健康文件，分别检查工作 PID、心跳、循环进展和成功 RPC，不把定时器仍运行视为接口健康。

单次连接最多恢复 3 次，间隔 5/15/45 秒，复用已安装模块。休眠且进程仍存在时允许暂停心跳；重建后工作层先检查系统电源状态再决定扫描。结束连接撤销令牌，重启或新连接不能复活旧任务。最近任务退出同时识别系统枚举与明确的 `User Request` 消息，保留原始原因不改写。

系统在下次创建界面时提供上次退出信息；`SystemExitStore` 本地保留 20 条完整原始记录，并标注预期重启、恢复检查和退出前会话状态。监督本身被系统清理等情况仍需用户重新连接；这不是系统级常驻资格。真机结果和未验证边界见[后台生存与恢复验证](LIFECYCLE.md)。

## 规则删除与统计

整应用重置和单条删除分别使用由界面写入的失效记录；工作模块维护规则文件。读取时按规则创建时间过滤失效规则与旧审批，点击前再次确认；删除前采集的候选和后台迟到写回不能恢复旧规则。后续的新采样可重新学习，重新取得启用状态。

概览“本次已跳过”使用当前会话的实际点击数；消失确认、保留、未能确认继续独立统计。显示组件使用状态属性更新，避免复用旧会话首次渲染的值。

## 主动学习

`ManualLearningWorker` 独立管理最多 60 秒的学习会话，只监听目标应用的系统 `COMPONENT_CLICKED` 事件。回调仅排队元数据，所有 UiTest 读取仍由主循环串行执行；训练期间不自动点击，也不计入无广告检查。

实际事件与点击前的新鲜布局按应用、窗口、类型、标识及范围对应；两次后续快照确认目标消失后追加已启用的手动规则。取消、离开应用或超时会清除内存布局；无法确认则不保存。后续匹配仍要求实时控件样式、位置和遮挡检查，不直接点击旧坐标。

规则保存 `origin` 与 `strategy`；旧规则按自动识别兼容。规则学习通知与跳过累计通知使用独立固定 ID，不把学到规则计为跳过。

## 识别记录与示意

`RecognitionProfile` 使用固定 S01～S08 和版本号，把首次学习策略、辅助证据、外形来源、内容分类、各部分相对窗口坐标、目标接收方式及必要容器层次共同保存。定义及策略文案由识别端和 UI 共用，见[广告识别方式](RECOGNITION.md)。`ProfileCapture` 只消费已读取的控件树，局部文本处理最多 128 个节点，保存最多 12 个内容部分和 12 层元数据；不保留整页文本或广告图片。用户自定义用词只允许从已确认的候选文字节点保留。

外形未知时默认画圆角矩形，不从正方形边界猜圆形。同组 Progress 圆环和 Circle 轮廓优先展示为圆形，装饰 Circle 不增加广告证据。`ButtonPreviewLayout` 使用统一缩放和位移保持左右、上下及叠放关系，`ButtonSample` 供规则页和策略页共用。profile 不参与规则键、审批或目标校验；已有规则只补充展示信息，预点击路径复用已保存记录，不增加图像识别。无效 profile 退回旧规则示意，不删除基础规则。点击、消失确认仍独立记数。

手动学习由前台页面等待工作模块注册点击监听，再通过应用声明的桌面入口打开目标应用；短时提高采样频率，终态返回轻启显示结果。结果按请求代次持久化确认，过期旧结果不自动弹窗，主动切换到其他应用时不抢回前台。
