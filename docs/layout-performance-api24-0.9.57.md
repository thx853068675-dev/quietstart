# API 24 单次快照执行与实机计时（0.9.57-test）

2026-09-16，Pura 70 Pro / OpenHarmony 6.1.1.120 / API 24。USB 保持连接；识别所用布局仍由手机自身通过已授权的 127.0.0.1 HDC 连接获取。本轮没有拔线、长时间保活或能耗验证。

## 改动与边界

1. API 24 已启用、具有按钮类型及展示信息的规则，先在当前完整布局中匹配。位置、文字/描述/ID、控件类型、父容器、禁用状态、场景排除、目标唯一性和遮挡仍会检查。匹配通过后核对当前前台及窗口范围、最新启用状态，再使用这次布局的坐标点击，不再必然导出第二份布局。
2. 新样式仍需两帧位置一致后学习，只有启用才执行。API 24 可以复用第二帧，避免再导出第三帧；OCR 仍只用于发现新规则时的兜底。API 26 的原生读取及双快照路径保留。
3. 已启用匹配直接携带原规则标识，减少点击前重复读规则、更新观察统计和写盘；点击前仍重新检查批准状态、删除记录及总开关。观察统计延后至输入后，删除的规则不会因迟到统计被重新启用。
4. 先筛选可能的按钮，再分析遮挡；先检查中心是否重叠，再检查控件层级。仍保留全部节点用于安全核对。解析后的私有树复用属性对象，避免逐字段复制所有普通页面控件；空文字直接结束文字匹配。
5. API 24 已启用规则使用读取 1100 ms、读取后 150 ms、总计 1250 ms 的预算（两项之和）。相较旧版的 700/300/800，增加平台导出预算、收紧读取后有效期，避免差几毫秒就重读整棵树。预算不是实际视觉响应时间承诺，且不包含输入调用本身。超时帧丢弃，不额外进入双快照链路。其他路径仍使用原预算。
6. 启动阶段若已经通过完整布局确认唯一前台应用，且读取后不超过 75 ms、读取耗时不超过 1100 ms，识别复用该次布局及原始时间戳；每轮只消费一次，不刷新旧时间戳冒充新帧。找不到前台窗口时，先用轻量窗口查询重试，最多一秒后才导出完整树兜底，避免连续读取桌面和启动动画；已确认需要完整树兜底的应用不重复等待这一秒。仅在接下来最多两秒内缩短检查间隔至 80 ms，正常待机及灭屏节奏保持不变。记录超过 250 ms 的前台查询和布局分段耗时。
7. API 24 布局连接中断先释放连接，最多连续重试两次；第三次仍失败才交给会话监督恢复。非终止异常保留在运行诊断中，但不会被错误归为应用退出原因。外部布局命令两秒发送终止信号，再过一秒强制终止；连接总超时仍为五秒。

单次快照意味着减少了一次目标位置采样，不能声称与双快照具有完全相同的时序保证。已知规则仍可能遇到按钮在读取后移动或系统响应延迟；当前窗口、时效与批准检查用于限制风险，不构成零误点保证。手动规则及旧的缺少类型/展示信息的规则可能继续使用原路径。

## 计时方法

不能把“发现前台 → 点击”或“匹配耗时”直接当成“广告出现 → 点击”。本轮在启动应用的同时，通过独立的 `snapshot_display` 连续抓取 32 帧，每帧记录手机自己的开始/结束时间；使用同一手机时间轴上的 `attempt.at`（输入调用开始）和 `clickSent.at`（输入调用完成）作比较。截图不通过识别器的 UiTest 控件读取接口。

逐帧确认最后一张未见广告/广告按钮的画面 A 和第一张已出现的画面 B。采样瞬间位于每帧抓取区间内，因此以 `[点击完成 − B.结束, 点击完成 − A.开始]` 报告保守时间区间。只在区间上界也不超过 1000 ms 时，称该样本经画面证实达标。广告图片尚未加载、但关闭按钮或广告交互区已出现时，也从该画面起计时。

采样间隔约 0.2–0.4 秒，不能伪造毫秒级视觉出现时间；抓图本身也增加负载。未出现广告、未发送点击、未采到完整转换及超时样本均保留，不能只统计最快样本。运行记录中的确认消失通常晚于实际页面切换，它是连续两帧事后核对，不属于点击前延迟。

## 回归验证

522 项离线测试全部通过；包括 API 24 单次当前树执行、两帧新规则学习、停用/删除/前台变化/移动/禁用/遮挡/过期拒绝、1050 ms 可用读取与 1120 ms 过期读取、一次布局中断恢复与三次连续中断停止、非终止异常不关联退出原因。单包构建和内外模块重签通过。

连续截图、设备运行记录及签名测试包存放于本地忽略目录 `dist/layout-performance-0.9.57/`，不随源码公开。报告只列经过核对的汇总数据，不公开手机画面或应用内个人信息。

## 实测结果与剩余问题

优化迭代共保留 70 轮连续截图（7 款应用），以及最终同一性能版本的 7 轮系统录像。前 60 轮涉及多份实验构建，存在超时丢帧、错过广告及未触发广告的情况，不能混成最终版成功率。

最后一组连续截图共 10 轮：智行、大麦各两轮，微博、驾校一点通、虎扑、下厨房各一轮，都发送了点击并确认原目标消失；12306 两轮未出现开屏广告。8 个广告样本中，5 个的保守区间上界不超过一秒；智行两轮为 469–1366 / 510–1192 ms，虎扑为 386–1012 ms，无法仅凭这种间隔截图判定是否达标。

随后切换系统录屏，关闭麦克风、开启显示触摸操作，不再连续调用截图命令。录像采用可变帧率，按原始帧 PTS 取样，不能用总时长除帧数当作恒定帧率。本轮 7 款应用均出现广告，均有一次点击记录、按钮上的系统触点及其后的页面退出；运行记录也均确认原目标消失。

### 捕获到的会话恢复

最后一组连续截图完成后、系统录像开始前，02:53:09 附近出现连续三次布局读取失败：前两次标记为非终止异常，第三次结束工作会话，监督任务随后自动重建，02:53:30 开始的新会话完成了上述七轮录像测试。没有将这次恢复混写成“全程无异常”。

当时错误为“布局命令未返回 JSON”，命令标准输出和错误输出被重定向到空设备，无法仅凭现存证据判定 UiTest 后端为何失败。最后追加诊断：保留命令退出码及最多 512 字节输出，成功时仍只返回布局 JSON；临时布局和日志同时清理。正常退出但未生成布局、非零退出及超时返回均有对应回归测试。该诊断补丁不改变点击、识别和重试上限。

当前恢复机制已经实测生效，失败源头尚不能断言根治。本次不包含 API 26 对照、拔线运行、整夜保活或能耗结论。

诊断补丁安装后的首次启动，还捕获到 `17000001 / Can not connect to AAMS, RET_TIMEOUT`，同时电脑侧临时界面读取也未获得有效布局。它发生在无障碍管理服务连接初始化阶段，不是广告规则判断失败；监督任务一次重试后已恢复。现有证据不足以认定是临时工具并发导致，或系统自身异常。该次记录也保留，不能以随后在线掩盖初始化失败。
