# 自己制作工具包（轻启 1.1.0）

工具包是一份 JSON 配置文档，用来描述**什么时候识别、识别哪个控件、执行什么动作、怎样判断结果**。它不是脚本，也不会在导入后立即点击；目标应用和对应规则还需要在轻启中启用。

## 从一份最小示例开始

下面的示例只适用于你指定的应用：进入应用后 12 秒内，如果发现文字为“我知道了”的控件，就生成一条点击规则，并以该控件消失作为结果。复制前请先把 `com.example.app` 换成目标应用的真实包名。

```json
{
  "schema": 2,
  "id": "example.confirm-dialog",
  "name": "确认提示框",
  "version": 1,
  "appliesTo": ["com.example.app"],
  "when": { "trigger": "app-foreground", "windowMs": 12000 },
  "steps": [
    {
      "find": { "by": ["text"], "match": ["我知道了"] },
      "do": { "capability": "click" },
      "expect": { "result": "gone" }
    }
  ]
}
```

| 字段 | 修改方法 |
|---|---|
| `id` | 给你的工具包取一个稳定的唯一标识，例如 `myname.confirm-dialog`。更新同一个包时保持 `id` 不变。 |
| `name` | 在轻启「工具包」页显示的名称。 |
| `version` | 从 `1` 开始；修改已有工具包后递增，便于区分版本。 |
| `appliesTo` | 填目标应用的真实包名。删掉这个字段表示不限定应用，初次制作建议保留。 |
| `when` | `app-foreground` 表示应用进入前台时开始观察；`windowMs` 是这次观察的毫秒数。 |
| `find.match` | 填目标控件实际呈现的文字。示例只识别完全匹配的“我知道了”。 |
| `do`、`expect` | 示例执行点击，并检查目标控件是否消失。 |

## 按场景修改

一份工具包可包含 1–8 个 `steps`。初次制作建议先写一步，确认能识别且不会选错控件，再增加其他步骤。

| 需要调整的地方 | 可用写法 |
|---|---|
| 只在指定应用运行 | 在 `appliesTo` 中填包名；它与轻启中的逐应用开关同时生效。 |
| 改变观察时间 | `when.windowMs` 可设为 1000–30000 毫秒；不写时为 12000 毫秒。 |
| 只在特定页面运行 | 用 `"trigger": "page-foreground"`，并在 `when.pagePath` 填页面名片段。读不到页面路径时不会触发。 |
| 使用控件描述 | 把 `find.by` 改为 `["desc"]`；文字与描述都要看时可写 `["text", "desc"]`。 |
| 接受多个文字写法 | 在 `find.match` 中列出所有允许的目标文字，例如 `["我知道了", "确定"]`。 |
| 要求额外页面依据 | 把 `find.explicit` 设为 `false`，并在步骤中加入 `"need": { "evidence": { "text": ["提示"] } }`。 |
| 排除某种语境 | 在步骤中加入 `"deny": { "context": ["删除账户"] }`，命中排除词时放弃识别。 |

`find.match` 是目标控件的白名单，页面上的其他文字不能替代目标。若控件没有文字，不要猜测它的文字；`image` 和 `structure` 路径需要更完整的目标与页面依据。1.1.0 尚未把 `find.by: ["id"]` 接入，直接填写会被拒绝。

### 动作和结果

示例使用最常见的 `"do": { "capability": "click" }`。1.1.0 还支持 `back`、`swipe`、`input` 等动作；这些动作的目标、参数和结果判据不同，建议先用点击示例熟悉导入与验证流程。

`expect.result` 可用 `gone`（目标消失）、`appeared`（指定文字出现）或 `text-changed`（目标文字变化）。`input` 不能配 `gone`。结果核对失败时，运行记录会显示未确认，不应把它直接当成点击未发出。

## 导入和验证

1. 修改示例，保存为 UTF-8 编码的 `.json` 或 `.txt` 文件；也可以直接复制完整 JSON。
2. 打开轻启的「工具包」页，选择文件导入或粘贴导入。确认工具包显示为已启用。
3. 在应用管理中启用目标应用，再打开该应用触发场景。若没有开启「规则自动启用」，到「规则」页确认新规则。
4. 在「运行记录」查看是否识别到目标、是否发出点击，以及结果记录。没有命中时，先核对应用包名、控件文字和观察窗口。

同一个 `id` 的文档再次导入会更新这个工具包。建议先只匹配一个明确的目标，在自己的设备上验证，再逐步增加场景。

## 导入后没有生效

按顺序检查：

1. 「工具包」页是否显示已导入、已启用；导入时报错时先检查 JSON 语法、字段名和取值。
2. `appliesTo` 是否为真实包名，目标应用是否在轻启中启用，自动执行总开关是否打开。
3. 如果规则需要确认，到「规则」页启用它；导入工具包与启用规则是两步。
4. 打开「运行记录」，看是没有发现目标、缺少页面依据、超出观察窗口，还是已经发出动作但结果未确认。

工具包可在轻启的「工具包」页复制或分享给别人；接收者仍需自行导入、选择应用并管理规则。
