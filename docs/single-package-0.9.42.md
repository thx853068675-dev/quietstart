# 0.9.42 单包安装验证

## 用户流程

只安装主 HAP → 初次向导 → 开启开发者模式与无线调试 → 填写端口并信任轻启 → 应用自动安装内置工作模块 → 等待新会话心跳 → 在线。后续重新连接会检查模块；已有匹配版本与安装回执时跳过传输。

单包指交付给用户一个安装文件；运行时系统仍有 entry 和 entry_test 两个模块。没有移除 UiTest 依赖，没有外网下载，不代表免签安装或 AGC 审核已通过。

## 真机结果（2026-09-13）

Pura X、HarmonyOS 7。卸载了原轻启和独立验证应用；确认轻启已不存在。随后电脑仅安装 0.9.42 主 HAP，系统仅列出 entry，首次启动前应用 files 目录为空。未导入旧规则、配置、回执或调试身份。

向导完整出现，生成新 RSA 身份并触发新的系统信任弹窗。点击应用内连接后，轻启通过本机 127.0.0.1 的授权 HDC 连接自行传输并安装 entry_test（94200），随后启动工作会话；新心跳确认成功，向导进入准备就绪。电脑没有安装测试 HAP 或代为启动这次工作会话。

另行通过 USB 调用已由手机安装的模块做自身按钮测试：1 项通过，0 项失败，3380 ms，UiTest 确认实际点击后出现成功标记。此独立点击测试不能冒充本机启动证据。测试结束后，再点击本机连接：4798 ms 恢复在线，包的 updateTime 未变化，证明没有重复安装。

本次真机测试主包为调试构建、设备授权调试签名，USB 保持连接用于操作界面及读取证据；未完成这版的物理拔线复测或 AGC 邀请安装。release 构建和标准 assembleApp 也通过，APP 外层只有 entry-default.hap，但当前签名配置不等同于商店发布签名。

- 31 项安装流程、LocalActivation 和 HDC 协议测试通过。

- 单包构建与标准 APP 构建通过；安装脚本语法检查通过。Windows 脚本未在 Windows 真机执行。
- 源码导出排除签名文件、工作模块 HAP 和生成的摘要清单。
